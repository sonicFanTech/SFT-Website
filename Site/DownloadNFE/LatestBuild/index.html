Noxen File Explorer: Razer Native — v2.0 R1

This page is for the latest public release of Noxen File Explorer. The RNR1 release is the first full native C++ rebuild of NFE and the main recommended version for current users.

Which build should I choose?
Build typeFile nameRecommended forBehavior
Normal build NoxenFE_RazerNative_v2_0_R1_Final_MSVC.zip Almost everyone This is the cleanest and easiest layout to update or troubleshoot. The EXE, runtime files, feature DLLs, 7-Zip files, and license files stay visible on disk.
One-file EXE build NoxenFE_RazerNative_v2_0_R1_Final_OneFile_FIX3_MSVC.zip Users who want a single-download package The EXE contains the private runtime payload. On first run it extracts the required files into the user profile and starts the internal runtime from there.
Recommendation: Use the normal build unless you specifically want the convenience of a one-file EXE.
Included highlights in v2.0 R1

Native UI foundation

Tabbed browsing, address bar, search box, sidebar, Home page, This PC, preview pane, settings, About window, and license windows are all part of the new native foundation.

MTP support

Phone browsing is built directly into the main program with dedicated support DLLs for device scanning, filesystem access, and actions.

Archive tools

Archive, ISO, and shortcut features are bundled with the release, including 7-Zip runtime support and 7-Zip File Manager integration.

One-file option

An optional one-file EXE edition is available for users who prefer a single downloadable executable rather than a visible runtime layout.

Installation notes
  1. Download the build you want.
  2. Extract the ZIP file into its own folder.
  3. For the normal build, run the main NFE EXE from the extracted folder.
  4. For the one-file build, run the single EXE and let it extract its internal runtime the first time it launches.
  5. If you want usage help after the first launch, open the Getting Started Guide.

The one-file EXE still uses extracted files behind the scenes because Qt platform plugins, helper EXEs, and external runtime files need to exist on disk in order to work correctly.
