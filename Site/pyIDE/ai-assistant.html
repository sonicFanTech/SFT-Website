AI Desktop Assistant

pyIDE AI Desktop Assistant

Status: Experimental - In Active Development. The assistant is being built directly into pyIDE v2.0 as a desktop coding and project helper. It should not be described as a magical autonomous agent with unlimited computer access.

The defining feature is controlled, permission-based access. The assistant is being designed to understand the active file, selected code, open tabs, and the currently opened pyIDE project only when pyIDE is permitted to provide that context.

Main Purpose

The assistant should help users with everyday coding work while keeping pyIDE in control of what project information is exposed.

  • Ask questions about code.
  • Understand the active file.
  • Understand selected code.
  • Inspect the currently opened project.
  • Search for text inside the active project.
  • Review files and suggest improvements.
  • Help locate bugs and explain errors.
  • Assist with changes while remaining under user control.
Permission-Controlled Project Access
Designed to require Allow pyIDE Control. When this option is disabled, project-control tools should not run. An active project folder must be open, and tool access is scoped to that active project folder.

The assistant should not silently inspect or control files. pyIDE validates the requested tool, rejects unsafe paths, and prevents path traversal attempts such as ../ from leaving the selected project. This is a deliberate user-control feature, not just a technical limitation.

Local AI Model Support

The current development setup has been tested with a locally configured coding model, including Qwen2.5-Coder 7B. That should not be read as the only supported model unless the application later makes it a hard requirement.

  • pyIDE is being designed around configurable AI model support.
  • Local coding models are part of the current development direction.
  • Compatibility and setup details may change before the final release.
  • Model configuration documentation will be expanded as v2.0 develops.
  • This page does not claim that every interaction is fully offline.

Designed to Keep the User in Control

The assistant should ask pyIDE for specific project information through a controlled tool layer. The user decides whether pyIDE control is allowed, and the active project acts as a boundary.

Future file-edit tools should remain recoverable and auditable. This page does not claim that the feature has completed a formal security audit.
