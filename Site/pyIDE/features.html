pyIDE Feature Overview

This page separates the working legacy Python release from v2.0 goals. The C++ recode is being built to preserve pyIDE's useful workflow, then improve it with a stronger native foundation and project-aware AI assistance.

Legacy release documentedv2.0 C++ recode in developmentAI assistant experimental
Code Editor Features

The original pyIDE editor is built around normal file editing instead of a heavy project system. v2.0 is intended to keep that straightforward feel while improving polish, responsiveness, and room for editor features.

  • Untitled files Legacy

  • Find and replace Legacy

  • Replace and Replace All Legacy
  • Undo and redo Legacy

  • Recent files Legacy
  • Configurable recent-file limit Legacy

Project Features

pyIDE uses an active project folder concept. In the legacy release this supports everyday file browsing and actions. In v2.0 that project boundary also matters for the AI tool layer.

Legacy workflow

  • Open an active project folder.
  • Use a dockable project-file tree.
  • Open files by double-clicking.
  • Create files and folders.
  • Rename or delete project files where supported.
  • Open locations in File Explorer.

v2.0 direction

  • Project-based workflows remain central.
  • Project searching is part of the AI tool milestone.
  • Active-project scope is used as a safety boundary.
  • The project system should be easier to expand in the C++ application.

Debugging

Debugging is documented cautiously. A complete v2.0 debugger should not be treated as publicly available until the C++ build proves it. The intended workflow includes breakpoints, start/stop controls, stepping, and clearer output/error visibility.

Status: debugging improvements are a v2.0 development area and future roadmap item, not a finished public release claim.
  • Basic debugging workflow and breakpoint management are intended for the recode.
  • Step controls should be added in a way that fits the lightweight IDE design.
  • Output and error visibility should remain easy to understand for beginners.
  • Future improvements should be documented only after implementation is verified.
Building EXE Files

The legacy Python release includes a built-in compiler window for a guided PyInstaller workflow. It is meant to help less experienced users package a Python script as a Windows executable without memorizing command-line options.

  • Built-in compiler window Legacy
  • PyInstaller-based builds for Python scripts Legacy
  • Guided EXE creation and build options Legacy
  • Dependency notes and clear errors should stay visible.
  • v2.0 should preserve the approachable compiler workflow when that part of the recode is ready.
Settings and Customization

The original application includes settings for normal desktop preferences. The C++ recode should keep configuration persistence clear and predictable.

  • Theme settings, dark mode, and light mode.
  • System or automatic theme behavior where supported.
  • Autosave configuration and interval.
  • Recent-file limit.
  • Completion settings.
  • External-console settings.
  • Interpreter management.
  • Session behavior.
  • Configuration persistence.
  • Portable behavior where supported.
  • Windows-focused design.
Languages and Documentation
v2.0 localization design goal: multiple interface languages should use external language files rather than hardcoded translations.

The planned v2.0 localization direction uses custom .langu files. Those files are JSON-based internally, which should make translation updates easier when new windows and features are added. Documentation should also become available in supported languages over time.

This is marked as a v2.0 design goal because implementation may still be incomplete.

AI Desktop Assistant

The AI Desktop Assistant is one of the largest planned additions for pyIDE v2.0. It is being designed as a permission-controlled project helper, not as an unrestricted computer-control agent.
