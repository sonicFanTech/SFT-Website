Frequently Asked Questions

Answers for the current C# rebuild, original Python edition, and companion tools.

Which version should I download?

Use VidPlayer v2.0.9.2 CS V1.0 for a modern Windows 10/11 x64 system. The Python edition remains available for the original implementation and historical use.

Does the C# build require .NET to be installed?

The precompiled release is self-contained. Extract the complete archive and keep its folders together.

Why are there separate repositories?

The C# and Python editions use different languages, project formats, dependencies, build systems, and release histories. Separate repositories keep both understandable.

Why does VidPlayer include VLC and FFmpeg?

LibVLC performs playback, while FFmpeg/ffprobe provide synchronized visualizer analysis, fallback data, and technical media information.

Does the visualizer use real audio data?

The C# rebuild can use real signed-16-bit LibVLC PCM callbacks. A position-synchronized FFmpeg path remains available as fallback.

Can I test a theme before saving it?

Yes. VPTheme Editor launches the protected Theme Environment Tester and can stream unsaved theme changes to it.

Can the Theme Environment Tester play audio?

No. It is intentionally a visual mock environment and does not initialize LibVLC.

What can VPACDRipper create?

WAV PCM, FLAC, and MP3 files through BASSCD and BASSenc.

Can I copy settings from the Python edition?

Many portable JSON, playlist, theme, and language formats are intended to remain compatible, but back up both installations and migrate into a separate C# folder first.

Where should I report C# rebuild bugs?

Use the Issues page in the VidPlayer-CSharp-Rebuild repository and include the version, steps, logs, and screenshots when possible.
